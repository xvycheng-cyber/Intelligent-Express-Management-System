
说明：

- 第 4 行用于展示无效行/人工修正；
- 第 5 行手机号 10 位，用于展示格式错误（如实际规则接受则调整）；
- 座机行用于展示多格式电话；
- 不包含真实快递收件人信息。

## 2. Schema 隔离

| Schema | 用途 |
| --- | --- |
| `express_address_book` | 正式业务库；演示数据不得无条件批量灌入 |
| `express_address_book_ms08_test` | 已存在的隔离测试库；本轮禁止启动/写入 |
| `express_address_book_test` | 旧测试库 38 行；禁止清理 |

演示前必须确认连接的是哪个 Schema；不能用测试 Schema 冒充正式库。

## 3. 演示前备份（人工）

仅在用户明确同意并已启动 MySQL 时执行；本阶段未执行：

```powershell
mysqldump -u root -p --single-transaction --routines --triggers express_address_book > backup_express_address_book_YYYYMMDD_HHMM.sql
```

要求：

- 口令交互输入，不写入命令行历史/脚本；
- 备份文件放用户指定目录，不入 Git；
- 记录备份时间、Schema、行数；
- 不在演示机上随意覆盖旧备份。

## 4. 恢复（人工、显式）

恢复会覆盖目标库数据，必须由用户确认后手动执行，本阶段不执行：

```powershell
mysql -u root -p express_address_book < backup_express_address_book_YYYYMMDD_HHMM.sql
```

恢复前：

- 确认目标 Schema；
- 再次备份当前数据；
- 确认没有其他使用者；
- 不得用恢复操作清理用户数据。

## 5. 演示数据写入原则

- 优先页面手工输入，不自动批量写库；
- 如果使用已有测试脚本，只允许指向明确隔离 Schema；
- 不新增自动写正式库的脚本；
- 不执行 DROP/TRUNCATE/全表 DELETE；
- 不修改正式 Schema；
- 演示结束不自动清理；是否清理由用户决定并记录。
