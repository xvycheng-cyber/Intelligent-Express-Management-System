## 1. 任务书硬性要求提取

### 1.1 任务选择

任务书要求"围绕以下两个任务，任选其一进行综合设计"：

| 选项 | 任务 | 本项目结论 |
| --- | --- | --- |

## 2. 业务规则（BR）

| 编号 | 规则 | 说明/理由 |
| --- | --- | --- |
| BR-01 | 一行文本对应一条联系人记录；空行忽略，但必须统计空行数 | 任务书"集中输入"，逐行对应最符合直觉 |
| BR-02 | 字段分隔符至少支持：中文逗号 `，`、英文逗号 `,`、Tab、中文分号 `；`、英文分号 `;` | 用户从 Excel/微信/邮件粘贴时分隔符不统一 |
| BR-03 | 解析不依赖字段固定顺序：电话通过模式识别定位，姓名取电话前（或电话后）的第一个姓名型片段，地址为其剩余原文 | 兼容"姓名，电话，地址"与"电话，姓名，地址"等顺序 |
| BR-04 | 地址必须"保留完整且原样"：只允许去掉地址首尾的分隔符与空白，**不得**按逗号/顿号/空格再次切分地址，不得改写内部标点 | 任务书要求"全部信息"，地址内部常含逗号（如"XX路,XX小区"） |
| BR-05 | 解析与保存彻底分离：解析接口不得写库；只有保存接口可写库；保存接口必须重新校验，不信任前端已解析结果 | 课程核心规则；防止"点识别即入库" |
| BR-06 | 部分行解析失败不得丢弃其它行：有效行照常返回并可保存；失败行保留原始行、行号与具体失败原因 | 任务书"供用户进一步保存确认"，不能因一行错全盘失败 |
| BR-07 | 每条解析结果必须携带**原始行号**（从 1 开始）与**原始行文本**，供人工核对 | 便于用户在长文本中定位 |
| BR-08 | 用户可以在预览表格中直接修改姓名、电话、地址；保存时以修改后的值为准 | 解析是辅助，人工确认是最终依据 |
| BR-09 | 同一批保存要么全部成功、要么全部回滚（事务） | 批量保存一致性 |
| BR-10 | 删除为逻辑删除（`is_deleted=1`），列表与详情默认过滤已删除数据 | 保护课程演示数据，避免误删不可恢复 |
| BR-11 | 批量删除必须校验：`ids` 非空、去重、单次上限 200、非数字/越界 id 拒绝 | 防误操作与恶意参数 |
| BR-12 | 所有写操作必须服务端校验：姓名非空且 ≤50 字、电话符合规则且 ≤20 字、地址非空且 ≤255 字 | 与数据库字段长度严格对齐 |
| BR-13 | 手机号识别支持 11 位大陆手机号；任务书示例的脱敏形态（`1[3-9]\d{2}[xX*]{4}\d{4}`）按"示例数据"接受，脱敏 `x` 原样保留（仅按 PR-03 去空格/短横等包装字符） | 见 §8 开放问题 Q-01，若教师要求严格可一键收紧 |
| BR-14 | 列表默认排序 `create_time DESC, id DESC`；关键词对姓名/电话/地址做或匹配 | 最新录入优先，符合录入场景 |
| BR-15 | 解析器必须是无状态纯逻辑：不访问数据库、不发起网络请求、不写文件、无随机数 | 保证可单测、可复现、可离线 |
| BR-16 | 日志不得输出完整手机号与完整地址；手机号中间四位打码、地址只保留前 6 字 | 个人信息保护 |
| BR-17 | 不引入注册、登录、会话、权限、验证码等身份体系 | 任务（一）无此要求，避免范围膨胀 |

## 5. 业务边界

### 5.1 范围内（In Scope）

1. 匿名单用户使用，无身份概念（不做注册/登录/权限）。
2. 多行文本 → 结构化联系人的解析与人工确认。
3. 地址簿的增、删（逻辑删）、改、查（分页 + 关键词）。
4. 批量保存、批量删除及其事务与校验。
5. 课程要求的 Web 基础实践页面（2.1～2.19）与 Servlet 映射演示（2.20）。
6. 论文素材：真实截图、真实测试记录、章节大纲。

### 5.2 范围外（Out of Scope，明确不做）

| 不做的事 | 原因 |
| --- | --- |
| 注册、登录、找回密码、角色权限、验证码 | 任务（一）无要求；任务书（二）的要求不适用 |
| 真实快递下单、运单查询、物流轨迹、对接快递公司 API | 与"地址簿录入与管理"无关 |
| 地图选点、地址标准化/纠错、经纬度、行政区划库 | 会显著增加复杂度，且与本项目核心（解析+管理）无关 |
| OCR 图片识别、语音输入、通讯录同步 | 超出课程范围 |
| Excel/CSV 导入导出 | P2，MVP 不做，避免范围膨胀 |
| 云端 AI 解析（把文本发到大模型） | P2；默认关闭，且必须脱敏与显式授权后才能做 |
| 多用户/多租户、审计日志、消息推送、缓存、微服务拆分 | 无必要中间件与架构膨胀 |
| 移动端/小程序/桌面端 | 只做桌面 Web |

### 5.3 以后可选（Backlog，不进 MVP）

- 重复联系人提示、地址去重、Excel 导入导出。
- 录入历史与撤销。

## 9. 文档一致性约定

1. **字段名**：数据库列用下划线（`receiver_name`），Java 属性与 JSON 字段用小驼峰（`receiverName`），前端 TypeScript 类型与 JSON 完全一致。
2. **接口前缀**：地址管理固定 `/api/addresses`；Servlet 演示固定 `/demo/**`。前端代理同时配置这两个前缀。
3. **响应外层**：`{ code, message, data }`，`code=0` 表示成功，具体错误码见 `api-design.md` §1.4。
4. **解析行状态**：`VALID` / `INVALID`，行错误码 `E1xx` 见 `parser-design.md`。
5. **编号唯一**：CR/BR/FR/NFR 在本文件定义；PR（解析规则）、API 错误码、TC（测试用例）、AC（验收）、MS（里程碑）分别在各自文档定义，互不冲突。
6. **不写未实现的能力**：任何文档与论文中出现的行为，必须在代码中可运行；未实现项统一标注 P2/Backlog。
