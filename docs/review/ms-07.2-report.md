## 2. Servlet 注册方式

启动类：

```java
@SpringBootApplication
@ServletComponentScan(basePackages = "com.express.addressbook.servlet")
public class ExpressAddressApplication { ... }
```

三个 Servlet：

```java
@WebServlet(name = "exactMappingDemoServlet", urlPatterns = "/demo/servlet/exact")
@WebServlet(name = "pathMappingDemoServlet", urlPatterns = "/demo/servlet/*")
@WebServlet(name = "extensionMappingDemoServlet", urlPatterns = "*.smap")
```

没有使用 `ServletRegistrationBean`，没有同时启用第二种注册方式，没有新增 `/` 的 Servlet。

真实容器日志确认：

```text
Tomcat started ...
Initializing Spring DispatcherServlet 'dispatcherServlet'
```

`/demo/servlet/exact` 的真实请求返回 `ExactMappingDemoServlet`，证明 `@ServletComponentScan` + `@WebServlet` 已生效。

## 5. 405 / 404 结果

### 5.1 自定义 Servlet 405

```text
POST /demo/servlet/exact        → HTTP 405
POST /demo/servlet/prefix/a     → HTTP 405
```

真实状态码为 405，没有被改成 200。

观察：

- 自定义 Servlet 只实现 `doGet`；
- POST 由 `HttpServlet` 方法分派拒绝；
- 错误响应由 Spring Boot 的 `/error` 机制输出 JSON（`status=405`），**不是** `ServletMappingDemoServlet` 的成功 JSON；
- 没有新增把 405 伪装成 200 的处理。

### 5.2 Spring MVC 405

```text
POST /demo/spring/method-only → HTTP 405
body: {"code":40501,"message":"请求方法不支持","data":null}
```

由现有 `GlobalExceptionHandler` 处理，证明 Spring MVC 路由看 HTTP 方法。

### 5.3 默认 `/` 与 404

```text
GET /demo/legacy/report.json → HTTP 404
body: {"code":40402,"message":"接口不存在","data":null}
```

- 该请求不匹配任何自定义 Servlet；
- 进入默认 `/` → DispatcherServlet；
- 没有 Spring Handler；
- 由全局异常处理器返回 Spring 的 404 JSON；
- **不是**自定义默认 Servlet 的响应；
- 没有新增 `@WebServlet("/")`。
