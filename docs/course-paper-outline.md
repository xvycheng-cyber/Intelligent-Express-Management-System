### 1.1 盒模型与显示类型（建议 900～1100 字）

应覆盖：

1. 盒模型四个部分（content / padding / border / margin）与尺寸计算方式。
2. `box-sizing: content-box` 与 `border-box` 的差别；本系统全局使用 `border-box` 的原因。
3. `display` 的常用值：`inline`、`block`、`inline-block`、`flex`、`grid`、`none`，以及"行内元素宽高为何无效""行内元素的垂直 margin 为何不生效"。
4. 行内格式化上下文与块级格式化上下文的差异（不必展开到规范细节，但要能解释现象）。
5. 外边距折叠（相邻兄弟、父子）的规则与规避方式。

本项目证据：

| 证据 | 位置 |
| --- | --- |
| 19 个演示小节 | `/web-basics` 的 2.1～2.5、2.6～2.8 |
| 表格/表单/卡片布局 | `AddressListView.vue`、`AddressFormDialog.vue` |
| 全局盒模型设置 | `frontend/src/styles/index.scss` |

常见扣分点：只抄概念、不解释"为什么行内元素设置 width 无效"；把 `inline-block` 与 `block` 的差别写反；截图与文字对不上。

### 1.2 布局（建议 1100～1300 字）

应覆盖：

1. 常规流（静态定位）是默认布局；块级纵向、行内横向。
2. `position` 五个值：`static`、`relative`、`absolute`、`fixed`、`sticky` 的参照物与是否脱离文档流。
3. 包含块（containing block）与定位上下文：绝对定位找"最近的已定位祖先"，没有则用初始包含块；`fixed` 通常相对视口，但祖先有 `transform/filter/perspective` 时会改变。
4. `top/right/bottom/left` 的生效条件与相互覆盖：同时设置时的拉伸、`width` 固定时的取舍、`margin: auto` 的居中用法。
5. 粘性定位与"粘性约束矩形"：sticky 只在最近的滚动祖先与父容器范围内生效。
6. Flex 与 Grid 的区别：一维 vs 二维；何时用哪个。本系统页面骨架用 Grid/Flex，而不是浮动。
7. 浮动：历史作用、`clear` 与 BFC 清除浮动；说明本项目为何不采用浮动做主布局（更可控、无需清除浮动）。

本项目证据：`/web-basics` 2.9～2.19；`AppLayout.vue` 的侧栏 + 主区；`WebBasicsView` 的粘性目录；2.18 线框仿制。

常见扣分点：把 `absolute` 说成"相对浏览器窗口"（那是 fixed）；忽略"相对定位不脱离文档流"；讲 sticky 不讲约束矩形。

### 1.3 MVC 模式（建议 800～1000 字）

应覆盖：

1. MVC 三要素职责：Model（数据与业务）、View（呈现）、Controller（请求编排）。
2. 一次请求在本项目中的完整链路（可复用 `architecture.md` §8 的 8 步）。
3. 后端分层：Controller → Service → Mapper → MySQL；Controller 保持"薄"的具体做法（不写 SQL、不写业务分支）。
4. 前后端分离下的 MVC 变形：View 由 Vue 承担，后端返回 JSON；Model 分居前后端，靠接口契约对齐。
5. 与 JSP/Servlet 时代 MVC 的差异：同一套思想，视图位置不同。
6. 分层带来的好处与代价（可测试、可替换；但类变多、需要契约管理）。

本项目证据：`controller/AddressController.java`、`service/impl/AddressServiceImpl.java`、`mapper/AddressMapper.java`、`frontend/src/api/address.ts`、`frontend/src/views/ImportView.vue`。

常见扣分点：把 MVC 与三层架构混为一谈；说"Vue 是 Controller"；举不出本项目的一条真实调用链。

### 1.4 Servlet 与请求URI的映射规则（建议 1000～1200 字）

应覆盖：

1. Servlet 容器（Tomcat）在请求进入时先做 URL 映射，再调用 Servlet 的 `service()`。
2. 规范规定的匹配顺序：**精确匹配 → 最长路径前缀匹配 → 扩展名匹配 → 默认 Servlet（`/`）**。
3. `servletPath`、`pathInfo`、`requestURI`、`contextPath` 的区别（配本项目 3 个 Servlet 的真实回显）。
4. `url-pattern` 的写法：`/foo`、`/foo/*`、`*.do`、`/`、空串。
5. Spring MVC 的 `@RequestMapping` 属于 DispatcherServlet 内部的 HandlerMapping，**不是**容器映射；差异包括：支持路径变量、看 HTTP 方法（405）、支持 `consumes/produces`、冲突检测方式不同。
6. 为什么本项目所有 `/api/**` 都进入 DispatcherServlet（因为 DispatcherServlet 注册在 `/`，作为默认映射）。
7. 常见误区：认为加 `@RequestMapping("*.do")` 等同于容器扩展名映射；认为容器映射会区分 GET/POST。

本项目证据：`servlet/ExactMappingServlet.java`、`servlet/PrefixMappingServlet.java`、`servlet/ExtensionMappingServlet.java`、`ServletMappingDemoController.java`、`/servlet-demo` 页面实测。

常见扣分点：只写"注解映射"不讲容器规则；把两层映射混为一谈；没有真实请求结果支撑。

## 5. 写作纪律（评审最容易扣分的地方）

1. **不写未实现的功能**：AI 解析、导入导出、登录、地址标准化都只可写在"不足与展望"，且必须标注"未实现"。
2. **不编造数据**：通过率、耗时、缺陷数只能来自真实执行记录；没有就写"本阶段未执行"。
3. **不使用任务书参考图冒充实现效果**：2.18 的原网页图可用（要标注来源），实现效果必须自己截图。
4. **截图不含真实个人信息**：手机号用脱敏演示数据；地址用虚构地址；不含数据库口令。
5. **术语统一**：收件人姓名 / 联系电话 / 详细地址；"容器映射（Servlet）"与"路由匹配（Spring MVC）"分开表述。
6. **时态与人称**：用"本项目/本文/本系统"，不用"我们觉得"；描述现象写"观察到"，不写"应该是"。
7. **图文一致**：正文引用的每个图号都在文中出现（"如图 X 所示"），每张图都有图题且在正文有解释。
8. **代码与文字一致**：文中描述的行为必须能在代码里找到；改代码就改论文。
9. **参考文献**：GB/T 7714 格式，优先 MDN、Servlet 规范、Spring 官方文档、MySQL 手册；不引用无法溯源的博客。
10. **查重**：概念部分用自己的话复述；代码片段与配置不计入正文查重但仍需标注来源。
